# 竞赛与项目答辩

比赛名称、届次、赛道、阶段和任务书决定内容；沿用 APW 的交付模式和证据链。先读取已提供材料，补齐会影响故事或规则判断的信息，再制作完整逐页概念。普通配色、版式和页数取舍由设计者按任务判断。

## 选择故事

| 场景 | 故事重点 | 主要证据 |
| --- | --- | --- |
| 大创立项 | 问题与依据、目标、方法、条件、分工、计划、预算和风险 | 申报材料、文献/调研依据、研究设计、资源与时间安排 |
| 大创阶段检查 | 计划与实际、阶段产物、偏差与变更、下一步 | 过程记录、原始数据、代码/原型版本、变更依据 |
| 大创结题 | 目标完成度、结果与限制、交付物、贡献、后续价值 | 报告、原始数据、实物/软件/作品、成果归属、经费记录及学校要求 |
| 科技发明制作 | 使用场景、技术原理、差异、原型、测试、应用边界 | 原型、设计与版本、测试条件/原始记录、知识产权材料 |
| 自然科学论文竞赛 | 问题/空白、方法、结果、解释、局限、原创贡献 | 文献、数据、实验记录、方法和引用 |
| 社会调查竞赛 | 现实问题、调查设计、现场证据、分析、建议 | 调查范围与时间、抽样/访谈记录、数据来源、隐私处理 |
| 创新创业路演 | 需求与目标对象、方案、验证、用户/市场、运营与收支、团队与计划 | 访谈、原型、试点、合同/订单、成本收入口径、真实贡献 |
| 工程、设计、职业技能等 | 按当届任务书选择原理、过程、成品、现场任务或答辩重点 | 设计稿、版本、测试、操作过程、作品及评分表对应证据 |

这些是可组合的故事模块；顺序、密度和页数由受众、讲解时长、真实内容与任务书决定。让每页承担明确任务，用场景、剖面、对照、流程、图表、影像和排版选择适合的表达。

## 大创按类型与阶段组织

创新训练重研究设计、实施、研究报告与交流；创业训练重商业计划、可行性和模拟运行；创业实践重基于成果的产品/服务及实际实践。模拟经营与真实经营分别标识。

立项完整故事回答“为什么做、要回答什么、如何做、条件是否足够、何时交付”；阶段完整故事回答“计划做到哪里、实际形成什么、为何调整、接下来怎么做”；结题完整故事回答“目标完成多少、成果如何核查、限制在哪里、团队贡献和资源使用如何说明”。分别为所选阶段规划完整演示。

教育部大创管理办法要求高校承担过程管理和结题验收。学校可能设中期检查；中期时间、表格、页数和评分以适用校级通知为依据。

## 规则和事实来源

正式备赛先核对当届主办方规则、赛道/组别方案及学校/地区选拔通知。把发布者与转载托管站点区分记录，保存 URL、本地快照、发布日期、适用届次/学校/赛道、条款或页码、检索日期和文件哈希。沿用 `brief.source_map` 与项目来源文件。

上一届文件明确标记适用年份；当届规则未公布时标记待确认。章程、年度通知、赛道规则、校赛时间和提交格式各有范围，评分维度与权重只属于对应版本和组别。

已有真实材料支持当前主张；估算写明假设，计划与已实现状态分别展示。示例测算和合成图表在内容附近标明。生成概念插画可用于说明装置和场景，实际照片、测试结果、合同、成果凭证仍须来自真实材料。

## 交付与检查

- `concept`：完整逐页概念、来源/参考与真实生成记录。
- `assets`：在完整概念基础上增加用户需要的独立透明素材。
- `assembly`：按编辑要求自动组装，检查当前 PPTX 的实际渲染、编辑行为与概念还原。

比赛场景本身不改变交付模式。整套先声明 `brief.delivery.expected_slide_ids`，再逐页生成、审阅和核对覆盖；单页探索明确标识其范围。保持概念设计的自由，不预设后续对象边界。

技术检查证明当前文件与声明的关系；逐页实际观看判断表达、可读性和视觉质量。代理审阅、用户视觉接受和正式赛事核验分别记录。
