# 阶段产出后，整批询问并等待回复

默认在实际产出的三个阶段各停下来一次：概念图、透明资产与独立组件、拼接后的 PPTX。用户看到可检查的结果后，决定是否调整。只做概念时确认一个阶段；概念加素材确认两个；自动组装确认三个。阶段反馈不改变已选择的交付模式。

## 每个阶段的共同顺序

1. 做好本阶段已约定的整套或批次，完成内部技术检查和代理审阅，准备当前版本的可查看产物。整套概念请求需要展示全部计划页面。
2. 展示一个整批审阅包，说明实际产出、仍存在的差异，以及本次询问覆盖的版本和范围。
3. 明确询问“是否需要调整”，提供“提出修改”和“确认当前阶段”的选择；说明确认后是进入已选模式的下一阶段，还是结束当前交付。
4. 提问后结束本轮并等待用户明确答复。在等待期间，后续阶段保持未开始，最终交付保持待确认。时间流逝、沉默、代理评分或技术检查通过都不能提供这份答复。
5. 用户提出修改时，用局部编辑或重做修好对应内容，展示新版本，再在同一阶段整批询问。明确确认后，才继续已选范围内的下一阶段或完成当前交付。

这是三个阶段的整批反馈；页面、单件素材和修复操作由 agent 内部检查，不再逐项增加询问。用户另有明确阶段、范围或确认要求时，按其要求执行。

## 三个审阅包与询问

| 阶段 | 先展示什么 | 询问示例 |
| --- | --- | --- |
| 概念图 | 全部当前页面、联系表/原尺寸入口、当前文案与示例标识；可按整套列出差异 | “这套概念图需要调整吗？请指出要改的页或内容；确认后我继续制作本项目已选的透明资产。”概念模式将后半句改为“确认后交付概念图”。 |
| 透明资产与独立组件 | 组件清单、真实透明文件的浅/深底预览、背景/字形/箭头等覆盖情况；全页素材附从空白重建对照；明确字体和内部像素的编辑能力 | “这批透明资产和独立组件需要调整吗？有没有漏件或与概念不一致的地方？确认后我继续本项目已选的拼接。”素材模式将后半句改为“确认后交付素材包”。 |
| 拼接后的 PPTX | 当前保存并重开的 PPTX、实际渲染、对应概念的并排对照、可下载文件和实际验证的编辑操作 | “这版拼接后的 PPTX 需要调整吗？请看排版、文字和还原效果；确认后完成本版交付。” |

问句应在本轮回复中自包含，直接指向当前产物。使用可用的用户输入工具；工具不可用时，在最终回复中展示产物并提问。收到回复之前，停在本阶段。将异步提问后的等待视为真实等待，而非调用后立即跨阶段继续。

## 回复与版本记录

在项目的 `provenance/stage-feedback.md` 按阶段追加：阶段名称、批次/版本、产物路径与哈希、实际问句、实际用户回复及对应处理。未回复时记录待反馈，不预填确认。现有导出器会保留项目的 provenance 文件；这是一份对话记录，不是新增的审批 JSON schema。

明确“确认，可以继续”只允许推进该审阅包及已选模式的下一步，不表示自动接受后面的素材或 PPTX，也不自动扩大为另一种交付模式。“收到”、泛泛的流程讨论或旧版反馈不足以确认当前产物。含义不明时，保持当前阶段待反馈并作简短澄清。

影响概念的修改重新确认该概念及依赖于它的后续产物；资产或拼接的修改返回受影响阶段，未变化范围的既有反馈保留。流程规则更新不补写历史样例的用户验收。

只有真实针对当前版本的用户反馈才记录用户视觉接受。阶段确认不自动代替正式项目的 G1–G5、品牌/事实决定或外部发布授权；若已有项目门禁覆盖同一版本与决定，可以合并为同一次询问。

## 技术状态与任务状态

`apw.py status/check/export` 现有结果表示文件与技术合同是否齐备，CLI 不验证用户是否实际回复，也不提供对话层的停等拦截。agent 必须执行本页规定：技术就绪后展示并停等。用户尚未回复时，对话状态为“等待本阶段反馈”，不能将技术状态中的 `complete-concept` 或 `complete-assets` 当成用户确认或已结束任务。

此前“低摩擦本地制作”“主 agent 负责验收”“继续”等一般授权，不跳过这里的默认三阶段询问。只有用户后来明确要求在特定任务/阶段免确认时，才按其新要求执行；保留该指令的实际范围。
