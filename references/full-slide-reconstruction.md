# 全页素材与从空白重建

用于用户要求“把背景、箭头、字形都拆开，能够从无到有拼回原构图”的本地展示。它是 `assets` 的可选全页范围；保留三种交付模式，不增加第四种模式，也不要求未来概念适配某种组件模板。

## 范围要先说清

普通 `assets` 可以只交用户指定的几张插画，机器核对的是已声明素材。这样的包不能称为“全页拆解”。用户要求全页重建时，在 `brief.json` 写 `delivery.asset_scope: "full-slide"`，保留有序 `expected_slide_ids`，并提供 `reconstruction-map.json`。画布大小、字体和拆分颗粒度由当前项目决定。

新本地展示选择这条路线时，不自动进入旧 strict/component-first 审批链。既有 strict 项目仍使用原合同；不得通过更换项目类型绕过既有批准范围。

## 逐页先列完整画面，再制作组件

进行两次清点：

1. 语义清点：背景、设备、人物、主插画、图表、文字、特殊标题字形、流程节点、连接管线和箭头。
2. 残余清点：阴影、反射、发光、支架、法兰、分隔线、底纹、徽标外壳、圆点、描边、角饰和遮挡补面。

记录每项的独立文件或原生源、位置与尺寸、层次、源概念哈希、用途及是否含数据。某设备内部固定构造可作为一幅插画，但五台可分别移动的设备不能为省调用次数合成一个资产。背景可以是独立不透明底板；要求透明的对象才检查真实 alpha。普通文本保留可编辑内容和字体映射。

简单箭头、连线和徽标可由独立 SVG / 原生图形表达；复杂材质按需用透明 PNG。SVG 源能编辑路径，不等于它在 PPTX 中以原生连接线存在。明确每个交付格式实际支持什么操作。

## 字体与特殊字形

从栅格概念图无法恢复原字体的软件文件。普通文字记录已安装字体、字号、字重、颜色、行距和替代差异；已有授权字体来源时再按许可交付或引用。短金属字、手写标识、立体标题可拆成准确文字的独立透明字形图，明确它是图像，改字需要重新生成。不得把生成字形图称作字体，也不得承诺未知字体已提取。

## 局部提示词编辑是正常修复手段

使用 Codex 内置 `image_gen`。先查看实际目标图，再附目标图并写明“只改哪里、怎么改、哪些区域保持”。整页概念可修复一处文字、图形或局部构图；拆件可修透明边缘、补遮挡、调整姿态；背景可删除前景并补出干净底板。一次处理一个目标组件，独立保留每次输出。

保留输入路径/哈希、实际附图、完整提示词、工具返回原路径、输出哈希和版本关系。局部编辑依然是生成式重建，可能改变未请求区域；检查目标区域与外围。要求严格像素不变或事实图件保持时，使用许可范围内的原始资产；不要让生成模型重造数据证据。

可用提示词骨架：

> 图 1 是实际编辑目标。仅将【目标区域/对象】改为【明确变化】，保持【构图、其他文字、其他对象、光线、透视】。不要增加【不需要的元素】。输出【整页/单独组件】；透明组件四周留完整透明边距，不要白底、棋盘底或裁断。对比原图检查非目标区域，保存为新版本。

## 从空白验证，而不是把概念当底图

用地图中的独立资产和原生源，从空白画布生成重建图。全页底板必须只含背景；不得藏着原概念的文字、前景或数据。对照原概念逐项检查语义与残余清点；查看透明对象在浅色、深色底上的边缘。确认全部组件隐藏后只剩空白。重建图和原概念分别保存并绑定不同哈希。

全页合同绑定每页概念、组件、原生源、渲染器、依赖文件、实际重建图与代理复核。它检查声明覆盖、几何和文件关联，不能自动发现漏画的物件，也不计算视觉忠实度。代理检查 `needs-repair` 会阻止全页导出；`agent-reviewed` 仅表示该版本被代理实际看过。用户接受只有真实反馈才记录。

`apw.py check ROOT --stage assets` 和 `apw.py export ROOT --output OUT` 核对全页合同。包内 `独立素材/` 同时包含透明对象与不透明背景；`项目证据/` 保留原相对路径的地图、源文件、渲染器、依赖和重建图，可解压后再次检查。旧指定素材包继续使用 `透明资产/`。

`assets` 模式的空白重建是检验素材是否足够的证据，不等于完成 PPTX。若同时请求拼装演示，PPTX 作为另一个明确标注的重建试验；正式 `assembly` 仍要检查当前 PPTX 的重开、实际渲染与承诺的编辑操作。

查看[三页全页拆解与逐层重建](../examples/showcase/full-rebuild/index.html)。它保留原概念，提供分层开关、组件清单和实际重建图；生成式设备与普通字体存在差异，不宣称无损或逐像素一致。
